1. Problem Interpretation
The problem is not the absence of individual software tools. The problem is the lack of a single operational chain 
connecting field evidence to management action. The proposed platform should therefore be designed around 
traceability rather than around a collection of disconnected dashboards.
Current failure
What the platform must change
Records are spread across spreadsheets, PDFs and separate 
systems.

Connectivity can be unreliable at mine sites.

Regulatory reporting is repetitive.
Generate structured reports from already captured records 
instead of retyping data.
2. Proposed Solution
The proposed product is a role-based web and mobile platform with one operational database and a small AI 
analytics layer. The platform is organized around five linked records: requirement, observation, action, evidence 
and verification.
Requirement -> Inspection / Evidence -> Observation or Violation -> Corrective Action -> Evidence -> Verification -> Closure
The central dashboard should not merely report that a mine has 18 open items. It should expose why the mine is 
high risk, which items are late, who owns them, and what changed since the previous reporting period.

5. Key Implementable USPs
The following USPs are implementable in a student prototype and are tied to specific product behavior. They 
avoid claims that depend on proprietary government systems or large hidden datasets.
1. Governance Risk Cockpit: Each mine receives a 0 to 100 risk score built from overdue compliance, violation 
severity, recurrence, corrective-action delay and selected operational anomalies. Every score is accompanied by 
a top-five reason list.
2. Violation Recurrence Fingerprint: Normalize observation category + mine zone + contractor + severity into 
a fingerprint. Detect repeated findings across inspections and mark the pattern as recurring when configurable 
thresholds are crossed.
3. Evidence Integrity Bundle: Every field finding stores GPS, timestamp, user identity, device time, photo hash 
and server receipt time. This creates a tamper-evident evidence trail without requiring blockchain for the MVP.

4. Offline Field Queue with Safe Sync: Inspections can be completed with no network. Each local record gets a 
temporary UUID, remains in a sync queue, retries automatically, and shows a clear synced / pending / conflict 
state.
5. Corrective Action SLA Ladder: A configurable timer changes state from due soon to overdue to escalated. 
The owner, supervisor and corporate reviewer receive different alerts based on severity and age.
6. Compliance Heatmap by Mine Zone: The GIS view aggregates findings by mine zone. A manager can filter by 
category, severity and date and immediately see concentration areas instead of only seeing a mine-wide count.
7. AI Report-to-Record Converter: OCR extracts date, mine, inspection type, finding, due date and named 
owner from a sample PDF or scanned form, then asks a human reviewer to confirm low-confidence fields before 
saving.
8. Risk Change Narrator: Instead of only showing a new score, the dashboard compares the current period with 
the previous period and generates a concise explanation such as: risk increased because three high-severity 
findings remained open and two compliance items became overdue.
9. Contractor Compliance Fingerprint: Calculate a contractor score using training completion, active 
violations, repeat observations and overdue actions. Compare contractors operating inside the same mine.
10. One-Tap Escalation Trace: Every alert carries a link to the issue, current owner, deadline, previous 
escalation and latest evidence. This removes the need to search across email threads.
6. End-to-End Operating Workflow
A. Compliance cycle
Requirement created -> due date tracked -> reminder -> submission -> evidence check -> approval -> next cycle
B. Field issue cycle
Inspector creates inspection -> observation captured -> severity assigned -> corrective action created -> owner notified -> evidence 
uploaded -> verifier checks -> closed
C. Risk cycle
Records aggregated -> features calculated -> risk score updated -> top drivers generated -> dashboard highlight -> alert if threshold 
crossed
D. Offline cycle
Form completed -> local encrypted store -> sync queue -> network check -> API submission -> server ID returned -> local record 
marked synced

11.1 Mine Risk Score
BaseScore = 0.30*Compliance + 0.25*Violations + 0.20*CorrectiveAction + 0.15*Safety + 0.10*Operations
Normalize each component to 0 to 100. Example: Compliance risk rises with overdue percentage and severity of 
late items. Violation risk rises with open severity-weighted findings and recurrence. Corrective-action risk rises 
with overdue actions and age of overdue actions. Operations can include production anomaly rate in the 
prototype.

20.1 System-level acceptance criteria

An inspector can create a field inspection with GPS, timestamp, description and photo.

An inspection created offline remains available until synchronization succeeds.

Every violation has an owner, deadline and status.

Every closed corrective action points to evidence and a verifier.

The dashboard shows mine risk with contributing factors, not only a single score.

GIS shows the inspection location stored in the database.

An overdue item creates a visible alert and escalation state.

All key state transitions create audit records.

No demo scenario requires editing production database rows by hand.

Fresh deployment plus seed script produces the same demo environment.
